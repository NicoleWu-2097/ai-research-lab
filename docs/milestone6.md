# Milestone 6：有界 Agentic RAG

研究请求先由模型选择路径，再由程序检查能力和预算。每轮取证后评估资料；证据足够才生成带引用的报告，不足时改写查询、调用 MCP，或停止。

## 运行

沿用 [M5 配置](milestone5.md)，启动数据库和应用：

```bash
colima start
docker compose up -d --wait
pnpm dev
```

API 默认启用 `AGENTIC_RAG_ENABLED=true`。`RAG_ENABLED` 控制向量检索，`MCP_ENABLED` 控制文档工具。设 `AGENTIC_RAG_ENABLED=false` 并重启 API 可回到 M5 固定流程。无需重新摄取未变更的文档。

多次模型调用共用 `MODEL_TIMEOUT_MS`，本地模型较慢时可设为 `180000`。流程由 `apps/api/src/research/agentic.ts` 的 LangGraph 状态图执行。

## 路径与限制

| 路径 | 行为 |
| --- | --- |
| 直接回答 | 用于问候、改写或无需来源的一般解释，报告明确标记未检索资料 |
| 本地检索 | pgvector 检索，每次任务最多 2 轮，可改写查询 |
| MCP 工具 | 最多 1 轮，真实子进程列出并读取一份本地 Markdown；不搜索互联网 |
| 证据足够 | 使用累计片段生成报告，保留 M5 引用校验 |
| 停止取证 | 证据不足、能力不可用、预算耗尽、重复查询或补充取证没有新片段时明确停止 |

单次任务最多 3 轮取证、4 次路由/评估模型调用、1 次 MCP 文档选择模型调用、1 次报告生成；最多保留 8 个片段。首次无命中仍允许补充检索。相同工具的重复查询按 Unicode、大小写、空白规范化检查；不同工具允许使用同一查询。

首次取证使用原问题，避免过早关键词化降低召回；改写查询仅发生在证据评估之后。

多轮片段按稳定 ID 去重，`[RAG:1]` 等引用编号只追加、不重排。MCP 文档分块后进入同一来源列表，其相似度为空。工具/检索实际失败直接终止任务，避免被误当成“无命中”。取消与总截止时间覆盖全部阶段。

MCP 文档按原文顺序分块，受累计 8 段上限约束，可能截断长文；当前没有重排器或自动扩容。

## 验收

在页面观察“研究过程”，或用 `/api/research/stream` 查看 `AGENT_DECISION`、`EVIDENCE_ASSESSED`、`RESEARCH_STOPPED` 事件：

- “你好，请用一句话介绍自己。”应可直接回答。
- “这个项目为什么选择 PostgreSQL 和 pgvector？请引用资料。”应取证后回答，展开检查来源。
- “这个项目的检索延迟具体是多少毫秒？请提供实测数据。”样例 ADR 没有该数据，应补充取证或停止，不能把规划当作测试结果。
- “请通过 MCP 读取模型适配器 ADR，解释为什么使用薄适配层，并引用资料。”应显示文档工具调用及来源。

上述四条路径已通过真实 Ollama、PostgreSQL 和 MCP 的 HTTP 验证。自动测试共 61 项通过（含单独运行的真实 PostgreSQL 测试 2 项）；类型、lint、格式和构建通过。

模型选择并非固定脚本；确定性分支验证见 `apps/api/test/agentic.test.ts`，包括真实 MCP 子进程测试。引用映射有效不代表语义一定正确，证据充分性仍是模型判断。M6 本身不包含多智能体或联网搜索，任务及决策事件不持久化。当前默认叠加 [M7 审查](milestone7.md)，设 MULTI_AGENT_ENABLED=false 可独立验证 M6。
