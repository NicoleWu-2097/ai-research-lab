# Milestone 9：完整研究循环

`计划 → 取证 → 研究与分析 → Critic → 补充取证 / 报告`

Critic 的反馈会进入下一轮检索计划。分析把结论分为观察和推断，每条必须引用已有片段并附逐字原文；前端点击 `[RAG:n]` 可展开对应来源。未解决问题或审查未通过时继续取证，预算用完后明确返回证据不足，不发布被否决的草稿。

## 运行与验收

沿用 [M6](milestone6.md) 配置，重启 `pnpm dev`。`RESEARCH_LOOP_ENABLED=true` 默认启用，需同时启用 Agentic RAG 与多角色审查；设为 false 回到 M7/M8。`A2A_ENABLED=true` 时沿用 [M8](milestone8.md) 的两个独立角色服务。无需重新摄取未变更的资料。

慢速本地模型可将各进程 `MODEL_TIMEOUT_MS` 设为 `300000`，主 API 的时限覆盖整个任务。

建议提交：

- “请只依据本地 ADR，说明 PostgreSQL 和 pgvector 的两条选型理由。”检查观察/推断、逐字引文及可点击来源。
- “这个项目的检索延迟是多少毫秒？请提供实测证据。”样例资料没有实测数据，应补充研究或明确停止。
- “你好。”应直接回答并标记未检索资料。

观察 `LOOP_PLAN`、取证、`LOOP_ANALYSIS`、`CRITIC_REVIEWED`、`LOOP_REPORT`、`LOOP_COMPLETED` 事件。模型路径可能变化，确定性边界见 `test/loop.test.ts`。

## 预算与边界

| 项目 | 上限 |
| --- | --- |
| 取证 | 共 3 轮，本地最多 2 次、MCP 最多 1 次 |
| 来源 | 累计 8 段，编号只追加 |
| 模型调用 | 12 次，包含规划、研究、分析、Critic、MCP 选择及重试 |
| 单次生成 | 4096 输出 token，适配器传给官方 SDK；截断不当作完整结果 |
| 文本预留预算 | 1,600,000 单位，调用前预留，用完停止 |
| 失败重试 | 本地非流式模型暂时失败最多额外 1 次；坏输出、流式输出和远程提交不重试 |

文本预算按 UTF-8 输入字节、schema、输出额度和固定开销估算；每次远程角色调用预留 200,000 单位。它是保守的成本控制量，**不是精确 tokenizer 计数、账单或美元限额**。实际费用仍取决于模型价格、隐藏输入及服务商计费；embedding 和 A2A 只读查询分别受取证次数和任务时限约束。

新循环只在发现新证据后重新分析；补充取证没有新增片段、重复查询、能力不可用或预算耗尽时停止。逐字引文存在不能证明结论逻辑成立，Critic 仍可能误判；真实试跑出现过引文复制错误，被校验拒绝并返回失败。

本轮按 step.md 的 M9 清单实现请求内循环，没有任务持久化或重启恢复；早期 ADR 中的 M9 持久化时间安排尚未兑现，待后续阶段落实。[M10](milestone10.md) 现已提供可选的持久化审批与节点间恢复。

验收记录：99 项测试通过（含 M9 经真实 A2A 子进程的集成测试），类型、lint、格式及构建通过。真实 Ollama/PostgreSQL 已完成逐项引文报告，以及 Critic 反馈→再次检索→证据不足停止两条路径；准确率和实际账单仍未做量化评测。
