# Milestone 10：人工介入与持久化审批

沿用 M9 配置和 PostgreSQL，启动：

```bash
HUMAN_ENABLED=true MODEL_TIMEOUT_MS=300000 pnpm dev
```

默认关闭人工介入；开启时要求 M9 和模型已配置。API 仅监听 `127.0.0.1`。无需重新摄取资料。

## 页面操作

1. 填写操作人和问题；可选“开始前先澄清研究范围”。
2. 查看子问题、查询和依据，调整查询后批准，或拒绝并结束。
3. MCP 文档访问和补充研究分别显示确认背景。当前 MCP 只读，不联网、不写入。
4. 刷新页面或重启 API 后，原浏览器仍可读取待审批任务并继续；运行中崩溃的任务可点“重启后恢复”。

浏览器保存当前任务 ID 和访问密钥；清除浏览器存储会丢失入口，请勿共享密钥。操作人是自报审计名称，不是登录身份。当前仅支持可信本机使用，不是多用户系统。

## 恢复语义

- 每个图节点执行前记录 `inflight`，完成后保存状态快照、下一节点、累计调用/文本预算和已用执行时间。
- 审批暂停发生在计划保存之后、检索之前。批准后从取证继续，不重新规划；拒绝和审批过期不会调用工具。
- 人工等待不消耗模型执行时限；审批默认 24 小时过期，可设 `APPROVAL_TIMEOUT_MS`（1 秒至 7 天）。查询或决定时检查过期并记入审计。
- 重启后，已保存的待审批或节点间快照可继续；原执行租约未到期时拒绝重复启动。租约为执行时限加 5 秒。
- 若崩溃发生在外部调用与结果落库之间，无法确定结果，标记 `interrupted` 并要求新建任务，不自动重放。不承诺分布式 exactly-once。
- 模型、工具及关键运行配置改变时拒绝恢复。已有来源快照保留，后续新检索仍可能看到更新的资料。

## 接口

开启后 `/api/research/stream` 返回 409，使用下列接口：

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/research/tasks` | `{question, actor, clarify}` 创建任务，返回 `{id,key}` |
| `GET /api/research/tasks/:id` | 查询快照、审批、报告和审计 |
| `POST .../:id/approve` | `{approvalId, actor, value?}` 批准；value 修改问题或查询 |
| `POST .../:id/reject` | `{approvalId, actor}` 拒绝 |
| `POST .../:id/resume` | `{actor}` 恢复已保存状态 |

除创建外均需 `x-research-key`；数据库仅存密钥哈希。审批使用唯一 ID 和数据库行锁，重复/旧版本决定返回 409。数据写入 `human_tasks`、`human_audit`，不改动 RAG 表。启动自动创建这两张表。

状态查询采用轮询，审批及节点操作记录持久化；完整 SSE 历史回放仍留给 M11。当前未接入任何写入或高风险工具，新工具需另行定义权限和幂等契约。
