# ADR 0004：默认接外部嵌入服务，保留 Ollama 路径

状态：已接受。日期：2026-11-17。

## 背景

本部署的聊天模型已经通过学校网关调用外部服务，嵌入向量由本机 Ollama 提供。没有安装 Ollama 的机器走不完上传与检索；嵌入服务不在线时，研究请求直接失败。配置里指向 Ollama 这件事也没有任何启动检查，配错要等第一次检索才暴露。

## 决定

嵌入默认接外部嵌入服务：`EMBEDDING_PROVIDER` 支持 ollama、openai、voyage、jina，默认 voyage；voyage 与 jina 使用 `EMBEDDING_API_KEY`，openai 使用 `OPENAI_API_KEY`。保留 `ollama` 提供方、`ollama` 依赖与既有代码路径，作为可选的本地路径。增加启动断言：开关打开时，聊天或嵌入的提供方仍为 ollama 就让启动失败。本记录接替 ADR 0002 中把 Ollama 作为本地默认模型来源的条款，该记录的其余决定继续有效。

## 理由与取舍

外部嵌入服务让一台没装本地模型运行时的机器只填一个 key 就能跑完上传、检索与出报告。Voyage 每账户前 2 亿 tokens 免费，按本项目 30 份、每份 24KB 的语料算，够全量重灌约一千次。保留 Ollama 的代码与依赖，是因为聊天侧仍提供 ollama 提供方，嵌入侧共用同一个提供方枚举；删除会同时改动模型边界、依赖与离线开发路径，换来的只是少一个被启动断言挡住的未使用分支。

被否决的替代方案是彻底删除 Ollama 代码与依赖。它缩小了依赖范围，但会让已经装好 Ollama 的机器失去离线路径，并迫使聊天侧一起改动；本部署要消除的是默认依赖，本地能力可以保留。另一个被否决的方案是只把默认值改成外部服务、不加启动断言。这样配置写错要等第一次检索才暴露，「本部署不依赖 Ollama」无法在启动时被检查。

## 后果

示例配置与部署文档按外部嵌入服务写。换嵌入配置后需要重灌；索引仍是全局单例，一次只能有一套嵌入配置。`ollama` 依赖继续留在仓库里，安装体积与升级成本照旧。启动断言的开关打开时，聊天或嵌入任一提供方为 ollama 都会让启动失败；需要走本地路径时把开关关闭。
